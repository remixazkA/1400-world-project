# Project role and implementation model

## Why this distinction matters

Project 1400 combines system design, geographic research, quality assurance and software implementation. Those responsibilities are not all performed in the same way, and this repository describes that division explicitly.

## My responsibilities

As project owner, systems designer and geospatial quality analyst, I am responsible for:

- defining the project's objective, scope and constraints;
- translating ideas into explicit functional requirements;
- researching and evaluating geographic and historical sources;
- deciding which variables should influence territorial formation;
- establishing regional targets, exceptions and validation criteria;
- reviewing proposed processing logic at a functional level;
- executing workflows and inspecting intermediate and final outputs;
- detecting, classifying and documenting anomalies;
- comparing iterations and deciding which changes to retain;
- maintaining consistency between local experiments and the global design.

## AI-assisted technical implementation

Python workflows are developed with AI assistance from requirements and feedback that I provide. My working cycle is:

1. define the intended behaviour and acceptance criteria;
2. review the proposed approach and clarify constraints;
3. execute the resulting workflow;
4. inspect logs, intermediate files, metrics and visual outputs;
5. identify mismatches between expected and actual behaviour;
6. specify corrections and rerun the test;
7. accept or reject the iteration.

I can inspect a script and understand its broad purpose and flow, but I do not claim independent Python programming ability or authorship of every implementation detail.

## Professional relevance

This model of work demonstrates capabilities relevant to functional analysis, manual QA, data quality and geospatial operations:

- requirements ownership;
- acceptance-criteria definition;
- structured testing;
- anomaly detection;
- root-cause reasoning;
- documentation and traceability;
- iterative decision-making;
- effective use of AI as an implementation tool without obscuring responsibility.
